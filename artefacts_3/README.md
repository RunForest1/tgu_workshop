# Этап 3: разведочный анализ (EDA) — комплект сдачи

## Запуск (из папки code/, рядом нужна папка с результатами этапа 2 и 3_eda/data из tgu_workshop)
```bash
pip install pandas matplotlib
python eda_build.py      # -> eda_sample.csv, network_availability.csv
python eda_analysis.py   # -> figures/*.png и *.csv (рисунки 1–6)
python eda_checks.py     # -> checks_results.csv, пересобирает всё и сверяет детерминированность
```
Пути к папкам с данными (этап 2 и `3_eda/data`) заданы в начале `eda_build.py` — поправьте под своё
расположение файлов перед запуском.

## Состав
- `eda_sample.csv` — исследовательская таблица снимков, ключ `(customer_id, snapshot_at)`, 21 548 строк, 2 458 абонентов.
- `network_availability.csv` — отдельная таблица доступности сетевых отчётов (region, measurement_month, snapshot_at) — "безопасный вариант" без прямого join в eda_sample.
- `analysis_plan.csv` — журнал 4 гипотез (H1 долг, H2 обращения, H3 время, H4 регион) с результатами.
- `checks_results.csv` — результаты проверок воспроизводимости из задания.
- `figures/` — 6 обязательных рисунков (PNG) и CSV с цифрами к каждому.
- `Отчёт_EDA.md` — отчёт по шаблону курса (разделы 1–7).
- `code/` — исходный код (`eda_build.py`, `eda_analysis.py`, `eda_checks.py`).

## Важное отклонение от примера в задании
Горизонт по уставу — ровно 30 дней (не календарный месяц), поэтому сетка T и даты
валидации/теста сдвинуты на месяц раньше предложенного в задании примера (обучение:
10.2025–06.2026, валидация: 07.2026, тест: 08.2026) — иначе T=09.2026 требовал бы данных
о расторжениях договоров вплоть до 01.10.2026 включительно, а журнал событий полон только
строго до этой даты. Рассуждение — в разделе 1 отчёта.
